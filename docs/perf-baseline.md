# Базовый профиль A4.1 и бюджеты

Замер 2026-11-08, до оптимизаций A4.2. Это исходная точка, с которой сравниваются исправления;
числа относятся к одной машине и не обещают ничего про другое железо.

## Как воспроизвести

```bash
cargo run --release -p dnd-perf-harness
```

Аргументов нет: harness сам создаёт две кампании во временном каталоге, наполняет их через
публичный `CampaignEngine::submit` и печатает таблицу. RNG детерминирован (`SplitMix64(7)`),
число выборок на команду — 120.

- **small**: 1 карта, 8 токенов, 2 персонажа;
- **large**: 20 карт, по 20 токенов, 20 персонажей (400 токенов);
- команды: `move_token` (частый горячий путь), `update_character` (запись листа с проверкой
  версии), `roll_dice` (RNG + сообщение чата), построение полного и персонального снапшота,
  экспорт (checkpoint + копия файла + ZIP).

## Окружение

- Linux 6.8.0, x86_64, 6 vCPU (Intel Xeon E3-12xx v2, 2.0 GHz), 11 GiB RAM;
- Rust 1.99.1, `--release`, SQLite из `sqlx` (WAL), без сети;
- кампании пустые по контенту: листы `{}`, без ассетов, без триггеров и плагинов. Это профиль
  «голого» конвейера, а не насыщенной кампании.

В строке «пакет» первое число — batch, который коммитит авторитет, второе — то, что получает
игрок после `filter_for_players`. Они совпадают, потому что пакет состоит из одного
`TokenMoved`, а скрытого в нём нет. Выбросы в `max` (8–13 мс) приходятся на первые выборки и
WAL-чекпойнты; p95 от них не страдает. Размер снапшота игрока совпадает с полным, потому что в
кампании нет скрытого контента и приватных полей — это ожидаемо для данного профиля.

## После A4.2: дельта вместо снапшота

`Resync(last_seq)` теперь восстанавливает дельту из журнала (ADR-0053). Замер на тех же
кампаниях: сколько занимает то, что клиент пропустил, по сравнению с полным снимком.

| кампания | 10 событий | 100 событий | 1000 событий | снапшот |
| -------- | ---------: | ----------: | -----------: | ------: |
| small    |      4 KiB |      45 KiB |       91 KiB |  53 KiB |
| large    |      4 KiB |      45 KiB |      224 KiB | 173 KiB |

Отсюда и предел: дельта, которая больше снапшота, не отправляется — сервер отдаёт снимок
(`MAX_DELTA_BYTES = 128 KiB`). Для типичного разрыва в десятки событий выигрыш — десятки раз.

Задержка команд после снятия трёх копий состояния на горячем пути (`apply`, `saves`, `items`)
на этой машине не изменилась за пределами шума: p95 «large» остался в пределах 1–2 мс. Копии
проверены структурно и покрыты тестами поведения; статистически значимый сдвиг на общей
виртуальной машине с 6 vCPU не наблюдался.

## Бюджеты (фиксируются до A4.2)

Бюджет — не текущее значение, а предел, после которого изменение считается регрессией. Запас
взят с большим коэффициентом, потому что машины игроков и серверов различаются на порядки;
задача A4.2 должна показать выигрыш относительно этих чисел, а не подгонять их.

- **Команда (p95, release, кампания «large»):** `move_token` ≤ 15 мс, `update_character` ≤ 25 мс,
  `roll_dice` ≤ 25 мс. Сейчас — 1.2–1.6 мс, то есть запас ×10 и больше.
- **Построение полного снапшота:** ≤ 50 мс при 400 токенах; сериализованный снапшот ≤ 4 MiB.
  Сейчас 0.1 мс и 173 KiB.
- **Персональный снапшот игрока:** ≤ 2 MiB и ≤ 50 мс; сейчас 173 KiB и 0.6 мс.
- **Экспорт кампании:** ≤ 5 с для кампании до 50 MiB; сейчас 23 мс на 1 MiB, то есть линейно
  ~1.2 с на 50 MiB.
- **Одна команда «перетаскивание токена» на игрока:** пакет ≤ 4 KiB (одно событие
  `TokenMoved`); сейчас 158 B. Бюджет относится и к дельтам A4.2: персональный пакет не должен
  вырасти на порядок.

Бюджеты относятся к серверу и локальной игре одинаково: конвейер общий (ADR-0001). Замер на
машине разработчика не заменяет приёмку R4.3 на целевом оборудовании.

## Что этот профиль не показывает

- Стоимость на насыщенной кампании: листы с сотнями полей, десятки плагинов, тысячи записей
  журнала, ассеты. Для A4.1 достаточно пустого конвейера; A4.2 должна добавить хотя бы один
  профиль с реальным SRD-листом.
- Трафик на игрока при живых дельтах: сейчас `Resync` всегда отдаёт полный снапшот (это и есть
  предмет A4.2), поэтому измерять нечего.
- Копирования: harness снимает только пиковую RSS процесса (12–13 MiB на пустых кампаниях),
  а не число копий `GameState` внутри `apply`. Прямой замер копирований остаётся за A4.2.
