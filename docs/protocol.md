# Протокол

Источник истины — крейт `crates/dnd-protocol`; форма JSON закреплена insta-снапшотами в
`crates/dnd-protocol/tests/snapshots/`, TS-типы — там же (`snapshots__typescript_bindings.snap`).
Решения о кодировании — [ADR-0007](adr/0007-protocol-encoding.md).

## Конверт

```json
{ "v": 7, "id": "<uuid>", "ts": 1760000000000, "seq": null,
  "session_id": "<uuid>|null", "sender": "<uuid>|null",
  "type": "intent", "payload": { ... } }
```

`v` ≠ версии получателя → отказ `protocol_mismatch` («обновите клиент/сервер»).

## Сообщения

| Направление     | `type`              | `payload`                                          |
| --------------- | ------------------- | -------------------------------------------------- |
| клиент → сервер | `intent`            | `{ intent_id, expected_version, intent }`          |
| клиент → сервер | `ping`              | —                                                  |
| клиент → сервер | `resync`            | `{ last_seq }`                                     |
| клиент → сервер | `get_journal_entry` | `{ id }` — текст записи (в снапшоте только индекс) |
| сервер → клиент | `events`            | `{ seq, caused_by, events[] }`                     |
| сервер → клиент | `snapshot`          | полное видимое получателю состояние                |
| сервер → клиент | `accepted`          | `{ intent_id, seq }` — только отправителю          |
| сервер → клиент | `rejected`          | `{ intent_id, reason: { code, ... } }`             |
| сервер → клиент | `journal_entry`     | `{ id, entry }` (`null` — нет или не видна)        |
| сервер → клиент | `pong`              | —                                                  |

Версия протокола — 7 (общее управление аудио — ADR-0028). Получатель видит не всё (ADR-0022): скрытое от него событие
приходит как `{ "kind": "redacted" }` с тем же номером, а когда видимость меняется целиком
(карту открыли игрокам, токен ушёл на слой мастера) — новый `snapshot`. Событие
`user_joined` создаёт сервер, когда участник входит в сессию; intent'а у него нет.

## История чата сессии (ADR-0022)

`GET /api/sessions/{id}/chat?before=<message UUID>&limit=50` требует токен участника этой сессии.
Без `before` возвращаются последние доступные сообщения; с ним — сообщения строго до указанного.
Ответ — массив `ChatMessageDto` от старых к новым, с сохранёнными именами авторов, временем и бросками.
Лимит по умолчанию 50, максимум 200; нулевой лимит и неизвестный курсор дают пустой массив.
GM и Co-GM видят всё; игроки и зрители — только публичные сообщения. Фильтрация применяется до
`LIMIT`, поэтому скрытые броски не обрывают историю игрока. Ошибка загрузки в клиенте допускает повтор.

## Пакеты установленных плагинов (ADR-0025)

`GET /api/sessions/{id}/plugins/{sha256}` с токеном участника возвращает `.dndplugin`
(`Content-Type: application/zip`, `Cache-Control: private, max-age=31536000, immutable`). Хэш —
64 строчных шестнадцатеричных символа; пакет должен быть установлен в этой сессии. Отсутствующий,
ещё не установленный или удалённый пакет даёт `404`, токен другой сессии — `401`.
Клиент ограничивает тело 256 МиБ и проверяет SHA-256 до кэширования и безопасного разбора пакета.

## Загрузка ассетов сессии (ADR-0004)

`POST /api/sessions/{id}/assets` принимает бинарное тело с токеном GM или Co-GM в `Authorization: Bearer`,
`X-Asset-Sha256: <64 lowercase hex>` и `X-Asset-Kind: webp | audio | plugin`. Файл ограничен
меньшим из лимита загрузки сервера и 100 МиБ; дополнительно действуют лимиты формата аудио/плагинов.
Сервер проверяет роль до чтения тела, SHA-256, формат и безопасно сохраняет файл под вычисляемым именем.
Повтор той же загрузки идемпотентен; успех — `204 No Content`.

Загрузка не регистрирует игровую сущность и не раскрывает файл игрокам. После файлов клиент отправляет
`register_asset` или `install_plugin` обычным пайплайном намерений. Офлайн-очередь сохраняется при ошибке
загрузки, чтобы повторить её с прежним `intent_id`.

Онлайн-импорт картинок и карт использует тот же порядок: все производные WebP загружаются до
`register_asset`, фон регистрируется до `create_map`. Повторный импорт использует канонический ID
по назначению и хэшу оригинала (ADR-0027). Исходное изображение не раздаётся игрокам.

Перед принятием нового `install_plugin` сервер сверяет DTO с безопасно прочитанным загруженным
архивом, проверяет `app_compat` и версии зависимостей. Отказ — `invalid` с полем `plugin.package`,
`plugin.incompatible_app`, `plugin.missing_dependency` или `plugin.dependency_version_mismatch`.
Повтор с прежним `intent_id` возвращает исходный результат даже после удаления пакета или изменения
зависимостей; исправленная установка должна использовать новый id (ADR-0015).

## Идемпотентность и повторы (ADR-0015)

- `intent_id` — ключ идемпотентности. Повтор **того же** intent (тот же `intent_id` и те же данные)
  возвращает исходный результат и ничего не применяет. Кэш хранит последние 10 000 intents или 24 ч;
  принятые операции вне кэша находятся по долговечной записи `event_log`, включая после перезапуска.
- Сервер хранит SHA-256 данных intent (`expected_version` + `intent`). Тот же `intent_id` с другими
  данными → `rejected { code: intent_id_reused }`.
- **Любой повтор с изменёнными данными — новый `intent_id`.** Например, после `stale_version` клиент
  перечитывает сущность и отправляет правку с новой `expected_version` под новым id.
- Повторно отправлять неподтверждённый intent после реконнекта нужно с прежним `intent_id` и
  прежними данными.
- `intent_id` и id создаваемых сущностей — UUIDv7. Сервер проверяет только версию и формат UUID;
  временная метка внутри id ничего не значит для правил и прав.

## Общее аудио (ADR-0028)

`set_sound_playback { asset_id, position_ms, paused, volume, looped }` — GM/Co-GM, LWW.
Ответ — `sound_played { sound }`; DTO содержит `position_ms` (0–86 400 000) и `paused`.
В снапшоте сохраняются looping или paused звуки, максимум восемь. Позиция — последняя
команда без часов и коррекции дрейфа. Player/Spectator могут только локально выключить звук.
См. [ADR-0028](adr/0028-shared-audio-playback.md).
