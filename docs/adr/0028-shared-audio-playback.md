# ADR-0028: Общее управление воспроизведением аудио

Статус: принято. Расширение P0 по запросу владельца, продолжение ADR-0026.

## Решение

GM и Co-GM управляют общей паузой, возобновлением и перемоткой через
`SetSoundPlayback { asset_id, position_ms: u32, paused: bool, volume: u8, looped: bool }`.
Команда использует LastWriteWins, не требует `expected_version` и порождает существующий
`SoundPlayed`. Player и Spectator получают `Forbidden`; выключение звука у слушателя
остаётся локальным состоянием клиента, без intent и события.

`SoundDto` содержит `position_ms` и `paused` с `serde(default)`: старые записи журнала
читаются как позиция 0 и отсутствие паузы. `PlaySound` и действия триггеров сохраняют
этот стартовый режим. Допустима позиция 0–86 400 000 мс включительно, громкость 0–100;
ассет должен существовать и иметь назначение Audio.

В состоянии и снапшотах остаются только звуки с `looped || paused`. Общий лимит —
восемь, включая приостановленные звуки без повтора. Обновление уже сохранённого
ассета не расходует новый слот. Возобновлённый звук без повтора становится временным
событием и удаляет прежнюю сохранённую запись этого ассета. `StopSound` удаляет запись
либо очищает все звуки. Проекция SQLite не создаёт строк для воспроизведения;
события проходят существующий event_log, открытие кампании остаётся беззвучным.

Ядро детерминировано и не использует часы: позиция — последняя команда, а не текущая
оценка времени воспроизведения. Клиент выполняет перемотку best-effort средствами
нативного аудиоплеера. Снапшот при подключении содержит последнюю заданную позицию;
коррекция дрейфа и компенсация задержки не входят в этот срез.

Протокол повышается до 7: клиенты версии 6 не умеют выполнять новую команду.
Обычная ссылка `[sound](asset:<id>)` в видимой записи журнала раскрывает метаданные
аудио через существующий `journal_pictures`; скрытая запись их не раскрывает.
Сама ссылка не запускает звук и не раскрывает папки библиотеки.

## Интерфейс библиотеки и вложений

Клик по файлу открывает вкладку его папки: слева соседние файлы, справа изображение либо плеер.
Вкладка одна на папку; смена файла меняет выбранный элемент. Клик по папке открывает её список.
Изображения карт можно просматривать из исходных WebP-тайлов, без повторного импорта.

Воспроизведение принадлежит сессии, а не React-вкладке. При закрытой вкладке плеер остаётся
компактным внизу окна. Только GM/Co-GM управляют общей паузой, позицией, громкостью и повтором;
игроки видят нейтральное название и могут отключить звук только у себя. После запрета autoplay
предлагается локальная кнопка разрешения воспроизведения. Закрытие кампании очищает звуки.

Ссылки журнала выбирают также картинки и аудио. `![name](asset:id)` показывает картинку,
`[name](asset:id)` для аудио показывает личный нативный плеер (пауза, перемотка, громкость).
Прослушивание вложения не отправляет игровую команду и не включает его остальным участникам.
Одиночные переносы строк сохраняются в просмотре Markdown; кодовые блоки не преобразуются.

## Проверки интерфейса

Тесты покрывают вкладку папки, состав списка, вложения журнала, переносы строк, очистку drag/drop,
права четырёх ролей в плеере, личное отключение звука и сохранение воспроизведения при закрытии вкладки.

Rust-тесты проверяют четыре роли, паузу/перемотку/возобновление, границы, общий лимит,
замену сохранённого звука одноразовым, старые команды и триггеры, видимость ссылок,
совместимость старых DTO и отсутствие сохранённого воспроизведения в SQLite.
