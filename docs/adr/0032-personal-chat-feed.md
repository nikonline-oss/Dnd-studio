# 0032. Личная лента чата и идентификаторы персонажей

- Статус: Принято
- Дата: 2026-11-02
- Скоуп: P1, PLR-4 из `ideas-backlog.md`

## Контекст

Системные сообщения содержали только отображаемое имя персонажа. По нему нельзя надёжно
построить личную ленту при переименовании или совпадении имён. Лента должна работать как
фильтр уже разрешённой истории, не расширяя видимость сообщений.

## Решение

`ChatMessageDto.related_characters` — список связанных ID с serde-default для старых событий.
Ядро заполняет его при бросках персонажей, инициативе, системных изменениях ресурсов,
состояний, предметов и жизненного цикла персонажа. UI не присылает эти связи самостоятельно.
Миграция 0023 сохраняет список JSON в существующей таблице chat_messages. История и живые
события возвращают одинаковые данные. Старые строки получают пустой список без угадывания ID.

«Моё» включает собственные сообщения по sender ID, сообщения с ID текущих принадлежащих
пользователю персонажей и текстовые упоминания текущего имени участника/уникального имени
его персонажа. Упоминания сопоставляются целиком, с Unicode-границами и экранированием
пунктуации. Для старых системных событий допускается точное совпадение текущего уникального
имени; явные ID имеют приоритет над именем. Неоднозначные старые имена не подставляются.

История загружается прежней авторизованной командой. Курсор и признак конца истории
вычисляются по нефильтрованным страницам, а не по числу совпадений в «Моё».

## Последствия

Новых игровых intents и зависимостей нет: ассоциации создаются в существующем pipeline
событий. Дополнительное поле обратно совместимо, версия протокола остаётся 9.
Имена на момент события сохраняются для отображения; новые связи переживают переименование.
Фильтрация не является личным каналом или авторизацией. Сервер продолжает исключать скрытое.
При передаче персонажа лента использует его текущего владельца. Старые события без связей
после переименования могут не попасть в личную ленту; они остаются доступны в «Все».
