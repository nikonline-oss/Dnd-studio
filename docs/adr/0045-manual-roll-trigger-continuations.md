# ADR-0045: Продолжения сценариев после ручных бросков

Статус: принято. Продолжение ADR-0043 по запросу владельца.

Шаг `change_resource` с `manual: true` сохраняет барьер в `PendingTriggerRun`:
список ID запросов `rolls`, уникальный ID ожидания в существующем поле `action`,
контекст, версию триггера, следующий шаг и переменные. Пустой `rolls` сохраняет
прежнее значение ожидания действия плагина; старые сохранения читаются с пустым
списком. Состояние остаётся в существующей SQLite JSON-проекции runtime.

Сценарий ждёт всех запросов своей группы, включая последний шаг. Повторная
активация того же контекста не создаёт ещё одно продолжение. Разные карты могут
ждать независимо; существующий лимит одного pending-запроса на триггер/персонажа
сохраняется, общий запрос может участвовать в нескольких контекстах. Внутренняя
отметка once на другой карте обновляет сохранённую версию ожиданий, поскольку
она не меняет определение сценария. ID новых
запросов проверяются на коллизии с сохранёнными и текущим batch.

После всех успешных ответов запись удаляется перед продолжением. Следующие шаги
получают `roll.count`, `roll.total` (сумма показанных результатов) и `roll.delta`
(сумма фактических знаковых изменений ресурсов). Суммы ограничены JS-safe range.
Новый ручной шаг или действие плагина может снова приостановить сценарий.
Выполненные шаги и отметка once не повторяются; каскадов других триггеров нет.

Отмена любого запроса, изменение/выключение триггера или потеря контекста снимают
остаток сценария и остальные pending-запросы группы. Уже выполненные шаги и
остальные выполненные запросы автоматически не откатываются. Прежняя явная
отмена rolled-запроса мастером по-прежнему обращает его конкретную delta.

Исправлена связанная ошибка простого ручного броска: теперь применяется именно
показанный результат. Отдельные кости урона бросаются только при наличии проверки
попадания; обычный бросок больше не бросает те же кости второй раз скрытно.

Продолжения и переменные не передаются игрокам. Контроллеры получают свои запросы;
ГМ видит прогресс ожидания в панели и управляет запросами существующим виджетом.
Лимиты: 128 продолжений, прежние 500 записей запросов. Произвольного кода нет.
