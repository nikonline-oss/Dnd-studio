# 0005. Универсальность систем правил

- Статус: Принято
- Дата: 2026-10-20

## Контекст

Приложение не должно быть привязано к D&D: любая НРИ подключается плагином. Значит, ядро не может знать
предметных понятий конкретной системы.

## Решение

- **Системный плагин** (`kind: "system"`) — ровно один на кампанию. Определяет схемы листов, ресурсы
  (обобщение HP), состояния/кондиции, формулу инициативы, пороги качественного здоровья, макросы бросков.
- Остальные плагины (`kind: "content" | "theme" | "ui"`) расширяют систему или работают поверх любой.
- Ядро не знает слов «сила», «класс брони» и т. п. Есть только сущности, поля, ресурсы, броски, формулы.
- **Минимальный expression language — в P0** (`dnd-expr`): арифметика, сравнения, `if/then/else`,
  `min/max/floor/ceil/round/abs`, ссылки на поля (`@str`, `@hp.max`); без циклов, пользовательских функций
  и доступа к чему-либо кроме переданного контекста; лимиты на глубину и длину. Полноценный DSL — пост-MVP.
- Движок костей (`dnd-dice`): P0 — `NdX`, модификаторы и ссылки на поля (`1d20 + @str_mod`), `d%`,
  keep/drop (`4d6kh3`), adv/dis. P1 — exploding (`!`), пулы успехов (`10d6>=5`), Fate (`dF`).

## Последствия

- Второй, принципиально иной системный плагин (`system-generic-d6`) — обязательное доказательство.
- Плагины декларативны и не исполняют код (см. CLAUDE.md §9).

## Рассмотренные альтернативы

- Жёстко зашитая SRD 5: быстрее старт, но противоречит цели продукта.
- Скриптовые плагины (Lua/Wasm): мощно, но небезопасно и вне скоупа MVP.
