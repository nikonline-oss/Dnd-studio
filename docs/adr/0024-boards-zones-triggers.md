# 0024. Поля, зоны и триггеры

- Статус: Принято
- Дата: 2026-10-28

## Контекст

Владелец проекта попросил общую вкладку-«поле»: мастер раскладывает заметки, ссылки на карты, записи
журнала и персонажей, картинки и связи между ними. Поле видят все, но что на нём видно — решают мастер
и **триггеры**. Пример: «персонаж, чей токен стоит в зоне карты, прошёл проверку Внимательности → на поле
для всех появляется карточка "Тайный проход"». Триггеры должны влиять и на персонажей: накладывать
состояния, атаковать, наносить урон, выдавать предметы. Шаблоны триггеров может поставлять плагин.

В ТЗ этого не было: граф миров — P2, полноценный DSL — пост-MVP, а §9 запрещает плагинам исполнять код.

## Решение

### Триггеры — данные, а не код

Триггер — запись «**Когда** → **Если** → **Тогда**», которую исполняет ядро:

- **Когда** (`event`): `roll_in_zone { zone, rolls }` — персонаж, чей токен в зоне, сделал один из бросков
  системы; `token_entered_zone { zone }` — токен был вне зоны и оказался внутри; `manual` — кнопка
  мастера; `item_received { name }` — у персонажа появился предмет (в списке инвентаря системы).
- **Кто**: `tokens` — токены, которые могут вызвать триггер; пусто — любой токен персонажа.
- **Если** (`condition`): выражение `dnd-expr` над полями персонажа (`CharacterFields`) и `@total`
  (итог броска события).
- **Тогда** (`steps`, 1–32): `reveal` (узел / поле / карта / запись / токен), `set_node_visibility`,
  `chat` (повествование, можно только для GM), `roll` (кладёт итог в `@roll` для следующих шагов),
  `change_resource` (урон или лечение костями, в границах 0..максимум; ресурс должен читать поле листа
  `@путь`), `add_condition` / `remove_condition`, `give_item`. У каждого шага — необязательное
  условие `when`. Атака = `roll 1d20+5`, затем `change_resource hp 1d6` с `when: @roll >= @ac`.
- Броски кнопками листа несут `roll` — id броска системы; ядро бросает формулу системы, и подделать
  «Внимательность» с +100 нельзя.

Выражения и кости проверяются при сохранении триггера (и при загрузке шаблона плагина). Никакого
исполнения кода, доступа к ФС или сети — только `dnd-expr` и `dnd-dice` над переданным контекстом (§9).

### Ядро исполняет триггеры детерминированно

- После `roll_dice`, `move_token`, `update_character` и `give_item` ядро проверяет только включённые
  триггеры подходящего вида. Если такие есть, события intent применяются к копии состояния, и триггеры
  смотрят на «до» и «после». Без триггеров лишней работы нет.
- События действий и `TriggerFired` дописываются в **тот же batch** — одна транзакция (ADR-0014),
  одинаково локально и на сервере сессий (ADR-0001). Броски — из RNG, переданного ядру.
- **Каскада нет**: события, вызванные действиями, триггеры не запускают. `once` — срабатывает один раз
  (`fired`). Не больше 64 срабатываний за intent.
- `manual` запускает только GM / Co-GM (`fire_trigger`); исполнитель действий — выбранный токен.

### Поля и зоны

- **Поле** (`boards`): `{ id, name, sort_order, visible_to_players }`. Их несколько; каждое открывается во
  вкладке центра.
- **Узел** (`board_nodes`): заметка (Markdown), ссылка на карту / запись журнала / персонажа, картинка
  из ассетов; позиция и размер в Units16 (ADR-0016). Видимость: `gm` или `players`. Перемещение — last-write-wins, как у токенов (ADR-0003).
- **Ребро** (`board_edges`): `from`, `to`, подпись, направленность, видимость.
- **Зона** (`zones`): именованный прямоугольник или многоугольник (≤ 64 точек) на карте или их
  объединение (`union`, ≤ 32 частей): зону можно перерисовать, дополнить частью и слить с другими
  (`merge_zones`: части объединяются, триггеры слитых зон переходят на итоговую). Только для GM.
- **Блок триггера** — узел поля `trigger`: название, событие, шаги, вкл/выкл, «Запустить»; от него к
  карточкам этого поля, которые он показывает или скрывает, рисуются линии (вычисляются, не хранятся).
  Ядро держит такие узлы `gm`, игрокам они не приходят никогда.
- **Триггеры** (`triggers`): хранятся в кампании, правят их GM и Co-GM.

### Видимость

Игрок получает поле, только если `visible_to_players`; узел — если он `players`; ребро — если видны
оба конца и оно само. Зоны, триггеры и `TriggerFired` игроку не приходят никогда (`Redacted`).
Раскрытие узла меняет видимость и идёт существующим путём `Resnapshot` (ADR-0022).

Видимость «конкретным игрокам» отложена: игроки получают один общий отфильтрованный вид
(`filter_for_players`), а адресная видимость требует фильтрации для каждого получателя на сервере.

### Библиотека картинок

- Картинки импортируются пачкой (`asset_import_images`) как ассеты `usage: token` (одна WebP до 2048 px;
  отдельного значения `usage` нет, чтобы не пересобирать таблицу ради CHECK). Повторный импорт того же
  файла переиспользует ассет.
- Раздел «Картинки» (GM): галерея с поиском, «На открытое поле», «Копировать для журнала».
- В журнале картинка — `![подпись](asset:<id ассета>)`: Markdown показывает только картинки кампании
  (схема санитайзера разрешает протокол `asset:`), чужие URL — только подписью. Игрок видит картинку,
  если она есть в открытой ему записи (`journal_pictures` в `PlayersSee`).

### Правила системы

- `SystemRulesDto` получает `conditions: [{ id, label }]` (состояния) и `inventory: { path, name_field }`
  (список в листе, где лежат предметы).
- У персонажа — поле `conditions` (id состояний системы); показывается на листе и на токене.
- `roll_dice` несёт `roll` — id броска системы (кнопки листа его передают), чтобы `roll_in_zone` знал,
  какой это бросок.
- Шаблоны триггеров: каталог `triggers/` в `.dndplugin`; параметры (зона, узел, бросок, DC) мастер
  заполняет при создании триггера из шаблона.

## Последствия

- Протокол — v5 (новые intents и events). Миграция campaign 0011.
- Поля закрывают часть «графа миров» (P2) в простом виде: без автораскладки и Cosmograph.
- Формы триггеров — фиксированный набор событий и действий. Расширение набора — новое событие или
  действие в протоколе и ядре, а не код в кампании.

## Рассмотренные альтернативы

- **Скрипты (Lua / JS / Wasm).** Гибче, но противоречат §9, требуют песочницы и ломают детерминизм ядра.
- **Триггеры на клиенте мастера.** Не работают, когда мастер офлайн, и расходятся с сервером.
- **Каскад триггеров.** Мощнее, но легко зациклить; отложено до появления лимитов и отладки цепочек.
