# ADR-0046: Явные игровые часы кампании

Статус: принято. Расширение по запросу владельца.

`CampaignMeta.game_clock` хранит прошедшие игровые секунды от условного начала
кампании и собственную optimistic version. Это общее публичное состояние,
независимое от версии названия/описания, времени компьютера и часов отдельных карт.
Старые кампании и snapshots получают 0 секунд и initial version.

Только ГМ/со-ГМ отправляют `AdvanceGameTime { seconds }`, с expected version часов.
Шаг 1..604800 секунд, назад нельзя. Счётчик сохраняет JS-safe точность с запасом
недели для дедлайнов. Ожидающие реакции, перемещения и pending-запросы бросков
блокируют продвижение, чтобы не менять длительности посередине решения.

`GameTimeAdvanced` переносит новые часы. SQLite использует существующий key/value
`campaign_meta` с ключом `game_clock`, без миграции таблиц. Имя/описание обновляются
из текущего состояния и сохраняют часы. Обычные receipts защищают повторную
доставку intent, в том числе после открытия БД заново.

Новая длительность `game_time` в определении содержит `seconds`, в эффекте —
абсолютный `until`. Продвижение удаляет все истёкшие эффекты одним batch; обычный
cleanup снимает поддержку/модификаторы. Реальные timestamps не расходуют игровую
длительность. Старые rounds, turns, turn_end и real_time сохраняют смысл;
продвижение часов не симулирует тики урона, раунды, отдых или восстановление.

Плагин может добавить карточку ГМ `kind: "clock"`; `items` — строки с целым числом
секунд для быстрых шагов. Пустой список использует 6/60/600/3600. Клиент показывает
предварительное подтверждение и отправляет сохранённую версию; чужое продвижение
снимает устаревшее подтверждение. Редактор триггеров и инспектор эффектов знают
игровые секунды. Пример SRD 0.10.0 содержит карточку и шаблон временной метки.

Это первый этап: автоматического перевода раундов в секунды нет, поэтому нет
двойного учёта параллельных боёв. Календарь, время суток, автоматическое применение
отдыха и периодические эффекты вне боя требуют отдельных деклараций/правил.
Protocol 18 добавляет часы, событие, intent и вариант длительности.
