# 0021. Папки журнала — сущности

- Статус: Принято. Уточняет ADR-0018 (папка записи была строкой-путём).
- Дата: 2026-10-23

## Контекст

В ADR-0018 папка записи — строка `a/b/c`. Папка существует, пока в ней есть записи: пустую создать
нельзя, переименовать или переместить папку целиком можно только правкой каждой записи (много
intents, конфликты версий на каждой). Журнал должен работать как проводник: папки создают,
переименовывают, перетаскивают и удаляют прямо в дереве.

## Решение

- **Данные.** `JournalFolderDto { id, parent, name, sort_order, version }`; `parent = None` — корень.
  У записи `folder: String` заменено на `folder_id: Option<JournalFolderId>`. Снапшот несёт
  `journal_folders` целиком (папок мало, текста в них нет). `PROTOCOL_VERSION = 3`.
- **Intents** (права — GM и Co-GM, как у записей):
  - `create_journal_folder { id, parent, name }` — создание, папка ставится последней;
  - `rename_journal_folder { id, name }` — проверка версии;
  - `move_journal_folder { id, parent, sort_order }` — проверка версии; нельзя в себя и в свои
    подпапки;
  - `delete_journal_folder { id }` — проверка версии; удаляет всё содержимое.
    `create_journal_entry` и `move_journal_entry` принимают `folder_id`; неизвестная папка — `not_found`.
- **Имена** уникальны среди соседей без учёта регистра (как в проводнике) → `already_exists`.
  Длина — как у заголовка записи. Глубина вложенности ≤ `MAX_FOLDER_DEPTH = 16`
  (и при создании, и при перемещении поддерева) → `invalid`.
- **Удаление рекурсивное, одним пакетом событий:** сначала `JournalEntryDeleted` для всех записей
  поддерева, затем `JournalFolderDeleted` от самых глубоких папок к удаляемой. Клиенты и проекция
  применяют события по одному и не видят «висящих» ссылок. Подтверждение с числом записей — в UI.
- **БД** (миграция campaign 0009): таблица `journal_folders` (`parent_id … ON DELETE CASCADE`),
  `journal_entries.folder_id … ON DELETE CASCADE` — каскад страхует проекцию, хотя ядро и так
  присылает удаления. Старые пути превращаются в дерево прямо в SQL (рекурсивный CTE по префиксам,
  id в формате UUIDv7 из случайных бит). Колонка `folder` остаётся и больше не читается:
  STRICT-таблицу без пересборки не изменить.
- **Видимость.** Папки не имеют своей видимости. Игроку UI показывает только папки, в поддереве
  которых есть видимые ему записи; серверная фильтрация (этап 4) следует тому же правилу.

## Последствия

- Переименование и перемещение папки — один intent и одна проверка версии, записи внутри не
  меняются.
- Пустые папки живут сами по себе.
- Порядок в дереве: папки, затем записи; внутри — по `sort_order`, затем по имени. Ручная
  сортировка перетаскиванием между строками — позже.

## Рассмотренные альтернативы

- Оставить пути и добавить intent «переименовать префикс»: одно событие меняло бы множество
  записей без их версий, а пустые папки всё равно пришлось бы хранить отдельно.
- Папка как запись особого вида в `journal_entries`: смешивает две сущности с разными полями и
  правами.
