# 0007. Кодирование протокола: идентификаторы, числа, теги

- Статус: Принято. Дополнено [0015](0015-intent-validation-and-idempotency.md).
- Дата: 2026-10-21

## Контекст

Протокол (`dnd-protocol`) сериализуется в JSON и экспортируется в TypeScript через specta. Нужно
зафиксировать решения, которые иначе всплывут как баги синхронизации.

## Решение

- **Идентификаторы** — UUID v7, генерирует **клиент** и кладёт в intent создания (`CreateMap.id`,
  `CreateToken.id`). Ядро остаётся детерминированным, клиент может оптимистично ссылаться на сущность.
  Повтор id → `Rejected { already_exists }`.
- **`Version` / `Seq` (i64)** экспортируются в TS как `number` через явный `specta_typescript::Number`.
  Значения не приближаются к 2^53. Метка `ts` — unix-миллисекунды (`i64`), в TS не экспортируется.
- **`f64`** (координаты, размеры) экспортируются как `number` (без `| null`) тем же способом. Ядро
  отвергает NaN/±∞ (`Rejected { invalid }`), поэтому `null` на проводе не появляется.
  `serde_json` собран с `float_roundtrip`: без него proptest нашёл потерю точности в последнем знаке.
- **Теги**: сообщения — `{ type, payload }` (adjacently tagged), intents/events — `{ kind, ...поля }`,
  причины отказа — `{ code, ...поля }`. Все имена — snake_case; коды отказов стабильны.
- **Update-intents** несут только изменяемые поля, `null` = не менять.
- **Create/Update-events** несут сущность целиком: применение идемпотентно и не требует прошлого состояния.
- **EventBatch** — события одного принятого intent; событие `i` имеет `seq + i`, в `event_log` одна строка
  на событие.
- `specta` — опциональная фича `dnd-protocol`; сервер собирает протокол без неё.

## Последствия

- Изменение формы JSON или TS-типов видно в ревью как diff insta-снапшотов.
- Клиенту нужен генератор UUID v7 (`crypto.randomUUID` даёт v4 — допустимо для уникальности, но для
  порядка используем v7-реализацию в `shared/ipc`).

## Рассмотренные альтернативы

- Сериализовать i64 строкой: лишний glue-код ради значений, которые никогда не превысят 2^53.
- Серверная генерация id: клиенту пришлось бы ждать ответа, чтобы сослаться на новую сущность.
