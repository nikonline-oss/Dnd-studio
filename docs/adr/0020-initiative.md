# 0020. Инициатива и бой

- Статус: Принято
- Дата: 2026-10-23

## Контекст

Этап 2a, шаг 10: трекер инициативы (CLAUDE.md §12, «инициатива (формула из системного плагина)»).
Системных плагинов ещё нет (этап 3), но формула и порядок ходов должны жить в ядре, чтобы локальная
игра и сервер сессий вели бой одинаково (ADR-0001). В §6 таблиц для боя нет.

## Решение

### Модель

- **Бой** (`combats`): `{ id, map_id, round, turn, version }`. Не больше одного боя на карту
  (`UNIQUE(map_id)` и проверка в ядре). Раунд начинается с 1; `turn` — чей ход, `None` до первого
  `next_turn`. Удаление карты удаляет её бой.
- **Участник** (`combatants`): `{ id, combat_id, token_id?, character_id?, name, initiative?,
sort_order, version }`. Обычно это токен карты боя (каждый не больше одного раза), связанный
  с персонажем. Можно добавить и участника без токена («подкрепление»). Удалённый токен оставляет
  участника в бою без токена (`ON DELETE SET NULL`). Не больше 100 участников в бою.
- **Порядок ходов** (`turn_order_cmp`, повторён в UI): инициатива по убыванию; участники без
  инициативы в конце; ничьи — по порядку вступления (`sort_order`), затем по id. Порядок полный и
  детерминированный.

### Intents и права

| `kind`             | Версия    | Кто                                               |
| ------------------ | --------- | ------------------------------------------------- |
| `start_combat`     | —         | GM, Co-GM                                         |
| `add_combatant`    | —         | GM, Co-GM                                         |
| `remove_combatant` | участника | GM, Co-GM                                         |
| `roll_initiative`  | участника | GM, Co-GM; игрок — за своего персонажа            |
| `set_initiative`   | участника | GM, Co-GM                                         |
| `next_turn`        | боя       | GM, Co-GM; игрок — когда сейчас ход его персонажа |
| `end_combat`       | боя       | GM, Co-GM                                         |

- `next_turn` проверяет версию боя: двойной клик (или два мастера сразу) не пропустит ход —
  второй получит `stale_version`. После последнего участника начинается новый раунд.
- Удаление участника, чей сейчас ход, передаёт ход следующему (раунд не меняется).

### Формула

- Ядро бросает по формуле `initiative_expression(sheet)`: `1d20 + @initiative`, если в листе
  персонажа есть целое поле `initiative`, иначе `1d20`. Так формула не знает правил конкретной
  системы (ADR-0005). На этапе 3 её даёт системный плагин.
- Бросок идёт через `dnd-dice` с RNG ядра и публикуется в чат обычным сообщением-броском (с
  кубиками), от имени участника. Участник, чей токен на слое GM или скрыт, бросает скрыто
  (видят GM-роли).

### Хранение и UI

- Миграция campaign 0008: таблицы `combats`, `combatants` (сверх §6, §6 дополнен).
- UI: вкладка «Инициатива» в нижней панели у всех ролей; на карте подсвечен токен, чей ход.
  Мастер начинает бой со всеми токенами карты, бросает всем, правит числа, передаёт ход и
  завершает бой (со вторым кликом). Игрок бросает за своего персонажа и завершает свой ход.

## Последствия

- Скрытых участников (видимых только мастеру) в списке пока нет: фильтрация видимости — этап 4.
  Игроки видят всех участников; бросок скрытого участника виден только мастеру.
- Эффекты с длительностью «до конца раунда», задержка хода и «готовые действия» — позже, поверх
  `round`/`turn`.

## Рассмотренные альтернативы

- **Хранить порядок явно** (список id в бою). Проще отрисовать, но каждый бросок переписывал бы
  список, а конфликты правок стали бы общими на весь бой. Вычисляемый порядок по инициативе
  проще проверять и не конфликтует.
- **Бой на всю кампанию**, не на карту. Отвергнуто: бой разворачивается на конкретной карте, и
  его токены берутся с неё.
- **Формула в трейте ядра** (`InitiativeRule`), как было в плане. Пока единственная реализация —
  функция; трейт появится вместе с системными плагинами, когда будет вторая.
