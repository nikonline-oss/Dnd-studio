# 0018. Журнал

- Статус: Принято. Папки — ADR-0021
- Дата: 2026-10-21

## Решение

- **Данные.** Запись: папка (путь через `/`, нормализуется ядром, корень — `""`), заголовок, Markdown
  (≤ 1 МБ), порядок в папке, видимость (`gm` | `players`), `players_can_edit`, автор, версия.
  Новые записи ядро ставит последними в папке — порядок не задаётся клиентом при создании.
- **Права.** GM/Co-GM создают, перемещают, удаляют и меняют всё. Игрок меняет только заголовок и
  текст записей, видимых игрокам и помеченных `players_can_edit`; видимость и флаг — нет.
- **Снапшот несёт только индекс** (`JournalEntryMeta` без текста). Текст запрашивается командой
  `journal_entry(id)` и кэшируется по `['journal', id]`; события `JournalEntryCreated/Updated`
  несут полную запись и обновляют этот кэш. Фильтрация по получателю — этап 4 (локально всё видит GM).
- **Черновик — UI-debounce 2 с** (CLAUDE.md §10): текст уходит intent'ом через 2 с после последней
  правки с `expected_version` версии, на которой начат черновик. При уходе со страницы раньше —
  отправляется сразу. Пока сохранение в пути, ввод продолжается и не теряется.
- **Конфликт версий** (`stale_version`): черновик остаётся в редакторе, автосохранение
  приостанавливается, пользователь выбирает «Записать мой поверх» (новая отправка с актуальной
  версией) или «Отбросить мой». Без «умного» слияния текста.
- **Рендер Markdown** — react-markdown + **rehype-sanitize** (схема в духе GitHub), сырой HTML не
  разбирается (`skipHtml`). **remark-gfm** (таблицы, зачёркивание, списки задач) — плагин к
  react-markdown из §3; без него привычная разметка таблиц не работает.
- **Ссылки не навигируют** вебвью приложения: показываются текстом с адресом в подсказке.
  Открытие во внешнем браузере (через плагин shell с белым списком схем) — позже. Внешние
  изображения блокирует CSP.
- Редактор — CodeMirror 6 (общий `CodeEditor`, языки JSON и Markdown).
- Связи журнала (`journal_links`) — этап 3 (§13).
