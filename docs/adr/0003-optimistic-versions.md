# 0003. Конкурентность: оптимистичные версии, а не приоритет ролей

- Статус: Принято
- Дата: 2026-10-20

## Контекст

Несколько участников (GM, Co-GM, игроки) правят общие сущности одновременно. «Побеждает тот, у кого выше
роль» молча теряет правки и не даёт пользователю понять, что произошло.

## Решение

- У каждой изменяемой сущности поле `version: i64`, начинается с 1, растёт на 1 при каждом изменении.
- Мутирующий intent несёт `expected_version`. Несовпадение → `Rejected { reason: StaleVersion, current }`.
- Права (кто _может_ менять) проверяет ядро по роли. Приоритет GM применяется только явно: GM может
  отклонить/перебить ожидающий запрос игрока.
- Исключение: позиции токенов — last-write-wins с серверной реконсиляцией, throttling 10–15 Гц.
  `MoveToken` не проверяет и **не увеличивает** `version` токена: иначе перетаскивание токена
  инвалидировало бы параллельные правки его свойств (видимость, слой, масштаб).

## Последствия

- Клиент обязан хранить версии сущностей и уметь показать конфликт.
- Создание сущности не несёт `expected_version`; удаление — несёт.

## Рассмотренные альтернативы

- Приоритет ролей / LWW для всего: потеря правок без уведомления.
- CRDT: избыточно для дискретных правок и сложно сочетается с авторитетными правилами.
