# 0001. Единое игровое ядро `dnd-game-core`

- Статус: Принято
- Дата: 2026-10-20

## Контекст

Игра идёт в двух режимах: локально (мастер готовит кампанию или играет за одним компьютером) и удалённо
через self-hosted сервер сессий. Если логика правил живёт в двух местах (в UI и на сервере), они неизбежно
разойдутся, а баги синхронизации станут основным классом ошибок.

## Решение

Вся игровая логика — чистая детерминированная функция без I/O в крейте `dnd-game-core`:

```text
apply(state, intent, actor, rng) -> Result<Vec<Event>, RuleError>
```

- Сервер сессий = game-core + WebSocket + SQLite сессии.
- Локальная игра = game-core внутри Tauri (in-process «сервер») с **тем же пайплайном намерений**.
- Фронтенд никогда не мутирует данные напрямую: отправляет intents, применяет events/снапшоты.
  UI-код одинаков для локальной и удалённой игры.
- RNG передаётся в ядро снаружи; в тестах — детерминированный seed.
- `dnd-game-core` зависит только от `dnd-protocol`, `dnd-dice`, `dnd-expr` (проверяется в CI).

## Последствия

- Ядро тестируется без БД, сети и Tauri — быстрыми property-тестами.
- Любая мутация требует новых вариантов `Intent`/`Event` в протоколе — больше церемоний, зато каждое
  изменение проходит проверку прав и версий в одном месте.
- Веб-клиент для игроков (P2) возможен без переписывания логики.

## Рассмотренные альтернативы

- Логика в TypeScript на фронтенде + тонкий сервер-ретранслятор: нет авторитетности, читерство, расхождения.
- Разная логика для локальной и удалённой игры: двойная поддержка.
