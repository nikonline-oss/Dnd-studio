# ADR-0034 — Декларативные действия, реакции и настройки плагинов

Статус: принято по ответам владельца от 2026-11-02. Расширение P0/P1.

## Решение

Формат пакета 2 расширяет существующую систему, а не заменяет её скриптами.
Старые пакеты формата 1 читаются; старые приложения отклоняют формат 2.
Протокол повышается до 10: клиент и сервер должны обновляться совместно.

Системный плагин объявляет `features` и `mechanics`. Он определяет условия,
досягаемость, типы перемещения, расходуемые ресурсы, сброс ресурсов в начале хода,
броски, область поражения и оформление. В ядре нет проверки идентификатора SRD
или отдельной встроенной реализации провоцированной атаки.

`feature_settings` — переопределения, принадлежащие кампании. GM/Co-GM меняют
отдельный флаг через `ConfigurePluginFeature`; игроки видят его без редактирования.
Флаг без переопределения использует default плагина. При обновлении сохраняются
переопределения оставшихся идентификаторов; входные настройки из пакета игнорируются.
Используется существующее событие замены описания плагина `PluginInstalled` и его
проекция. Изменения разных флагов не перетирают друг друга; для одного флага LWW.
Личные видимость и яркость эффектов хранятся в настройках устройства.

Ядро предоставляет ограниченные примитивы: выход отрезка перемещения из области
досягаемости, предложение реакции, ожидание решения, расход ресурса и продолжение
перемещения, бросок атаки/спасброска и изменение ресурса. Плагин составляет из них
правило. Досягаемость измеряется в клетках, координаты — Units16. Для square-grid
измеряется расстояние между занятыми клетками с поправкой на scale токенов;
метрику (Chebyshev/Euclidean) выбирает плагин.

Одновременные предложения упорядочены по пересечению границы и ID. Движение ждёт
решения контроллера первого предложения; мастер может принять, отклонить или
отменить оставшееся движение. Нельзя закончить ход, пока есть ожидание реакции.
Выбор правила и расход реакции повторно проверяются авторитетным ядром.
Повторная команда разрешения завершённого ожидания отклоняется.

Ожидания сохраняются в SQLite и входят в снимок. Игрок получает только предложения
своих видимых токенов против видимой цели; зритель не получает их. Изменение
владельца и состояния ожиданий вызывает персональный реснапшот. Удаление сущностей,
смена/настройка системы отменяют ожидания, оставляя токен в последней зафиксированной
позиции. Автоматического тайм-аута нет: мастер может отменить ожидание.

Действие `plugin_action` в триггере обращается к тому же исполнителю, что действие
на карте; новые виды действий не дублируются в правилах конкретной НРИ внутри ядра.
Параметры исходного пакета проверяются схемами и повторно ядром при установке.

## Первый проверочный набор

SRD 5.2: опциональная провоцированная атака и Fireball 3 уровня. Источник правил:
https://media.dndbeyond.com/compendium-images/srd/5.2/SRD_CC_v5.2.pdf.
Атрибуция SRD сохраняется в манифесте. Generic d6 продолжает работать без новых правил.

Это основа стандарта и два примера, а не полная автоматизация D&D. В частности:

- выбор оружия пока заменяет пример ближней атаки с настраиваемым бонусом;
- `can_see`, `can_react`, `disengaged` выставляет мастер/контроллер в листе;
- нет автоматического LOS, стен, укрытий, высоты и всех особых свойств существ;
- область сейчас круглая, цели определяются по центрам токенов, один персонаж
  получает изменение ресурса один раз, даже если представлен несколькими токенами;
- звуковые эффекты новых действий, конусы и линии потребуют следующих расширений;
- ни этот срез, ни наличие листа SRD не означают реализацию всего справочника правил.
