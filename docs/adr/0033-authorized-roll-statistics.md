# 0033. Статистика доступных бросков

- Статус: Принято (P1, PLR-10)
- Дата: 2026-11-02

## Контекст

Снапшот и страницы чата содержат только часть истории. Вычисление статистики на клиенте
давало бы неполные результаты. Агрегаты скрытых бросков также раскрывают информацию:
фильтрация должна происходить до подсчёта на авторитетной стороне.

## Решение

`CampaignDb::roll_statistics(role)` одним SQL-запросом агрегирует `dice_rolls` вместе
с `chat_messages`. GM и Co-GM учитывают все броски, Player и Spectator — только публичные.
HTTP `GET /api/sessions/{id}/roll-statistics` требует токен участника этой сессии;
роль берётся из авторизованного участника, а не из параметров запроса. Локальный сервер
использует свою роль. Через IPC обе ветки доступны как `roll_statistics`.

Группировка использует ID автора. Имя — последнее записанное в доступной получателю
истории, поэтому скрытый бросок не раскрывает даже новое имя автора. Два пользователя
с одинаковыми именами остаются разными строками. При отсутствии ID, например после
удаления пользователя, применяется историческое имя; одинаковые такие имена объединяются.
Автоматические броски без автора также группируются по записанному имени.

Для каждой группы возвращаются количество, средний итог, минимум/максимум и количество
оставленных кубов d20 со значением 1 или 20. Отброшенные кубы не считаются; d200, d6,
константы и модификаторы не влияют на эти два счётчика. Они не называются критическими
исходами: значение критов определяется системой правил. Среднее объединяет полные итоги
разных выражений и не является оценкой равномерности кубов.

Период — вся сохранённая история текущей кампании/серверной сессии, включая загруженный
архив: отдельные границы игровых вечеров пока не записываются. Это явно указано в UI.
Раздел чата обновляет статистику раз в 10 секунд, только пока открыт, и по кнопке.

## Последствия

Новых мутаций, миграций и зависимостей нет. DTO добавлен в протокол, HTTP и IPC;
существующие сообщения и версия WS-протокола не меняются. Память клиента зависит от
числа групп, а не числа бросков. Полный проход по истории выполняет SQLite; для очень
больших историй впоследствии можно добавить агрегированную проекцию после измерений.

Проверки: реальные SQLite-файлы и все четыре роли; скрытые броски, переименование,
совпадающие имена, пустые данные, оставленные/отброшенные d20 и d200; локальная игра
после переоткрытия; HTTP без токена/с чужим токеном, история более 200 сообщений;
UI загрузки, повторного запроса, пустого состояния и сохранения черновика чата.
