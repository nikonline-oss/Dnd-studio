# 0027. Идентичность производных изображений и импорт во время сессии

- Статус: Принято
- Дата: 2026-10-30

## Контекст

Один исходный файл можно использовать как фон карты и как картинку библиотеки. Для карты
создаются тайлы, для картинки — уменьшенное изображение. Уникальность только по хэшу оригинала
мешала создавать карту из уже импортированной картинки: ядро требует фон с назначением `map`.
После объединения навигации импорт фонового изображения также нужно открывать с доски.

## Решение

- Ассет уникален по назначению и SHA-256 оригинала. В SQLite это `UNIQUE(type, usage, sha256)`;
  аудио продолжает храниться как `type=audio, usage=token` согласно ADR-0026.
- Миграция 0018 пересоздаёт таблицу, сохраняя данные и явно восстанавливая ссылки карт и токенов,
  которые `ON DELETE SET NULL` очищает при удалении старой таблицы. Проверки внешних ключей
  остаются включёнными. Перенос атомарен и использует обычный резервный бэкап перед миграцией.
- GM/Co-GM импортирует карту с панели инструментов доски. После создания карты обычный intent
  добавляет на текущую доску карточку-ссылку, затем открывается карта. Карта и карточка изначально
  скрыты от игроков. Отмена диалога ничего не создаёт.
- Импорт картинок и карт использует тот же захват контекста кампании, что импорт звука (ADR-0026).
  Онлайн клиент загружает все уникальные хэши миниатюры, изображения и тайлов до `RegisterAsset`.
  Хэш оригинала для идентичности не предоставляет игроку доступ к исходному файлу.
- При конкурентном импорте используется канонический ID ассета с тем же назначением и хэшем.
  Фон регистрируется до `CreateMap`; метаданные появляются только через авторитетные события.
- Офлайн-копия GM хранит файлы и обычные intents в очереди ADR-0004. После локального импорта UI
  получает полный снапшот: seq локальной копии может быть ниже последнего серверного seq в UI.
  Это также применяется к звуку и повторному импорту без новых событий.

## Последствия

Новых зависимостей, вариантов протокола и форматов ассетов нет. Для одного оригинала могут
существовать две записи с разными производными; файлы по совпавшим хэшам по-прежнему общие.
Старые кампании и их ссылки сохраняются. Если добавление карточки отклонено после создания карты,
карта остаётся в кампании; ошибку показывает интерфейс, её можно привязать существующей ссылкой.

## Рассмотренные альтернативы

- Ослабить проверку фона карты: у картинки нет необходимых тайлов и другого допустимого размера.
- Изменять существующий ассет при импорте карты: это меняло бы представление уже используемых
  картинок и нарушало бы неизменяемость записей импорта.
- Отключить внешние ключи внутри миграции: SQLite не применяет такое переключение в транзакции.
