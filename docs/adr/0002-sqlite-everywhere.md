# 0002. Хранилище: SQLite везде

- Статус: Принято
- Дата: 2026-10-20

## Контекст

Кампания должна переноситься между клиентом и сервером без конвертации, а self-hosted сервер — подниматься
одной командой без внешних СУБД.

## Решение

- Кампания на клиенте = один SQLite-файл (WAL) + папка ассетов.
- Сессия на сервере = **такой же** SQLite-файл + ассеты: `/data/sessions/{id}/campaign.sqlite`.
  Одна схема и одни миграции (крейт `dnd-db`); экспорт = отдача файла.
- Индекс сервера (сессии, участники, аудит) — отдельный `/data/server.sqlite`.
- PostgreSQL и S3 в MVP не используются. Файлы — через крейт `object_store` (локальная ФС по умолчанию,
  S3 — опционально пост-MVP).
- Миграции только вперёд.

## Последствия

- Загрузка кампании на сервер и выгрузка обратно — копирование файла, без маппинга схем.
- Масштаб сервера ограничен одной машиной; для целевой нагрузки (≤100 сессий × 20 участников) достаточно.
- Таблица `pending_ops` существует в общей схеме, но используется только клиентом.

## Рассмотренные альтернативы

- PostgreSQL на сервере: лишний сервис для self-hosting, две схемы.
- Собственный файловый формат (JSON/ZIP): нет транзакций и частичных обновлений.
