# 0010. Логирование

- Статус: Принято
- Дата: 2026-10-21

## Контекст

CLAUDE.md §10: панель логов (по умолчанию warn+error), ротация 5 × 10 МБ. В стеке (§3) — `tracing`,
`tracing-subscriber`, `tracing-appender`, но `tracing-appender` умеет ротацию только по времени.

## Решение

- `tracing` везде; в десктопе подписчик из трёх слоёв: файл, stderr (только debug-сборки), кольцевой буфер.
- Файл пишет собственный `RotatingFileWriter` (по размеру: `dndstudio.log`, `.1` … `.4`, по 10 МБ) под
  `tracing_appender::non_blocking`. Новых зависимостей нет. Логи — в `app_log_dir()` ОС.
- `tauri-plugin-log` не используется: он построен на крейте `log`, а серверу сессий нужен тот же `tracing`.
- Кольцевой буфер (2000 записей) отдаётся командой `logs_recent`, новые записи — событием `LogRecord`.
  Панель фильтрует по уровню (по умолчанию warn+error) и строке, умеет копировать.
- Фильтр: наши крейты — debug (dev) / info (release), прочие — warn. Фронтенд пишет в лог через
  `log_frontend` (Error Boundary). Паники логируются хуком.

## Последствия

- Логику ротации покрывают наши тесты, а не внешняя библиотека.
- Сервер сессий (этап 2/4) переиспользует `RotatingFileWriter` — при его появлении writer переедет в общий крейт.
