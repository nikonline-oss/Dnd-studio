# 0026. Журнал: ссылки, таблицы, импорт/экспорт; библиотеки с папками; звуки

- Статус: Принято
- Дата: 2026-10-28

## Контекст

После проверки ADR-0024 владелец попросил (расширение P0, как ADR-0024): ссылки между записями
журнала; таблицы — и внутри текста, и отдельной записью «как Excel»; импорт и экспорт журнала;
папки в библиотеке картинок; библиотеку музыки и звуков с папками; проигрывание звуков триггерами.
Форматы обмена выбраны без новых зависимостей: Markdown и CSV (Word/Excel — нет). Формул в таблицах
пока нет, но формат не должен им мешать.

## Решение

### Ссылки

- В тексте журнала (и везде, где рендерится Markdown) ссылка на элемент кампании —
  `[текст](journal:<id>)`, также `map:`, `character:`, `board:`. Клик открывает элемент во вкладке.
- Протокол не меняется: ссылка — часть текста. Видимость не нарушается: если получатель не видит
  цель (её нет в его снапшоте), ссылка показывается обычным текстом без перехода.
- Редактор вставляет ссылку в позицию курсора через форму выбора элемента (как картинку).

### Таблицы

- Внутри текста — таблицы GFM (`| a | b |`), они уже рендерятся; добавлены стили.
- Запись-таблица — та же запись журнала (папки, видимость, правка игроками, версии, ADR-0021),
  у которой вместо текста `table: { columns: [{ name, width }], rows: [[ячейка]] }`.
  `JournalEntryMeta.kind` = `text | table` — для значка в дереве. В БД — колонка
  `journal_entries.table_data` (JSON, `NULL` у текстовых записей).
- Ячейка — строка, как её ввёл пользователь. **Формулы — позже**: ячейка, начинающаяся с `=`,
  зарезервирована под формулу (`dnd-expr` со ссылками на ячейки, вычисление в клиенте, хранится
  исходная строка) — формат данных при этом не меняется. Сейчас `=` показывается как текст.
- Правка — как текст: черновик с debounce 2 с, целиком `UpdateJournalEntry { table }` с
  `expected_version`; конфликт — та же панель «применить мою / отбросить».
- Лимиты: ≤ 64 колонок, ≤ 5000 строк, ячейка ≤ 4000 символов, весь JSON ≤ `MAX_JOURNAL_BYTES`.

### Импорт и экспорт журнала

- Экспорт (GM): выбранная папка на диске получает дерево папок журнала; текст — `Название.md`,
  таблица — `Название.csv` (RFC 4180, UTF-8 с BOM — его понимает Excel, первая строка — названия
  колонок). Ссылки `journal:<id>` становятся относительными путями к файлам (`../Папка/Запись.md`),
  как в Obsidian; ссылки `asset:` остаются как есть.
- Импорт (GM): выбранная папка становится папкой журнала (вложенные — вложенными); `.md` — текст,
  `.csv` — таблица. Относительные ссылки на `.md`/`.csv` и вики-ссылки `[[Название]]`,
  `[[Название|текст]]` превращаются в `journal:<id>`. Скрытые папки (`.obsidian`, `.git`)
  пропускаются. Импортированные записи — «только мастеру».
- Rust читает и пишет файлы (только в папке, выбранной в диалоге, §9; имена проверяются ещё раз,
  без `..` и разделителей; лимиты 2000 файлов, 1 МиБ на файл, глубина 16), а план — папки, записи,
  ссылки, имена файлов — строит фронтенд чистыми функциями и отправляет обычные intents. Поэтому
  импорт одинаково работает и локально, и в удалённой сессии.

### Библиотеки с папками

- `LibraryFolderDto { id, library: images | audio, parent, name, version }` — папки отдельно от
  журнальных: у них нет видимости и порядка (сортировка по имени). У ассета — `folder_id`.
- Intents: `CreateLibraryFolder`, `RenameLibraryFolder`, `MoveLibraryFolder`, `DeleteLibraryFolder`,
  `MoveAsset { folder_id }`, `RenameAsset { name }` — только GM/Co-GM. Удаление папки удаляет
  вложенные папки, а ассеты возвращаются в корень (ассеты неизменяемы и могут использоваться картами).
- Игроки папок библиотеки не получают.
- БД: таблица `library_folders`, колонка `assets.folder_id` (`ON DELETE SET NULL`).

### Звуки

- Аудио — ассет `usage: audio` (mp3, ogg, wav, flac, m4a, webm; ≤ 50 МиБ). Файл не
  перекодируется: отдаётся как есть под именем `assets/<sha256>.audio`, MIME — в записи. Колонку
  `usage` с CHECK из 0007 нельзя расширить без пересборки таблицы, а пересборка `assets` с
  включёнными внешними ключами обнулила бы ссылки карт и токенов, поэтому в БД аудио отличает
  колонка `type = 'audio'` из 0001 (`usage` у таких строк не читается).
- `PlaySound { asset_id, volume, looped }` и `StopSounds { asset_id? }` (GM/Co-GM) и действия
  триггера с теми же полями → события `SoundPlayed { sound }` / `SoundStopped { asset_id? }`.
  Зацикленные звуки (музыка) лежат в состоянии `sounds`, приходят в снапшоте — переподключившийся
  слышит ту же музыку. Состояние звука не сохраняется в БД: после закрытия кампании тишина.
- Игроки не получают аудиоассеты библиотеки (имена файлов — спойлеры). `SoundDto` несёт `sha256` и
  MIME без имени; хэш аудиофайла — «право» на его скачивание: сервер отдаёт файл аудиоассета любому
  участнику, а узнать хэш можно только из события.
- Клиент скачивает файл (`fetch` → Blob → `blob:`-URL; CSP: `media-src blob:`) и играет его;
  громкость у каждого своя (ползунок в строке статуса, хранится локально).

## Последствия

- Протокол v6 (новые поля с `#[serde(default)]`, новые intents/events), миграции 0015–0016.
- Ассеты в удалённую сессию по-прежнему уходят архивом при создании сессии; загрузка новых
  картинок и звуков во время сессии — этап 4 (как в ADR-0024).
- Каскада триггеров по-прежнему нет: звук от триггера не запускает другие триггеры.

## Рассмотренные альтернативы

- **Таблица как Markdown-текст.** Нет типов колонок и ширин, сложно править как сетку, формулы
  пришлось бы парсить из текста.
- **Импорт/экспорт целиком в Rust.** Пришлось бы дублировать сборку intents и разрешение ссылок для
  локальной и удалённой игры; чистые функции на TS проще тестировать.
- **Отдельная таблица для аудио.** Ассеты уже адресуются по хэшу, архивируются и отдаются одним
  путём — второй путь только удвоил бы код.
