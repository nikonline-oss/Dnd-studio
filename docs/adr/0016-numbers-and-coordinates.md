# 0016. Числа и координаты в игровом состоянии

- Статус: Принято
- Дата: 2026-10-21

## Контекст

Состояние игры вычисляется ядром на сервере и (в будущем) предсказывается клиентом в JS. Числа с
плавающей точкой плохо переносят детерминизм между платформами и языками: одна и та же формула может
дать разный результат, а `f64` требовал `float_roundtrip` даже для сериализации. Expression language
(этап 3) будет считать формулы — их значения должны быть точными. Координаты, привязанные к
пикселям изображения, «уезжают» при замене картинки в другом разрешении.

## Решение

- **Целые `i64` для всего, что участвует в правилах и синхронизации:** HP, ресурсы, результаты
  формул и костей, инициатива, координаты и размеры на карте. Все значения, уходящие в TS, —
  в пределах ±(2^53−1) (ADR-0015).
- **Логические единицы карты.** У карты фиксированные `width`/`height` (`i64`, логические единицы),
  задаются при создании; по умолчанию — размер исходного изображения в пикселях. Изображение
  растягивается на эти размеры, поэтому замена или переимпорт картинки в другом разрешении не
  сдвигает токены. Размер карты после создания не меняется (в 2a).
- **Координаты — `i64` в 1/16 логической единицы** (`UNITS16_PER_UNIT = 16`): токены, операции тумана
  и всё будущее позиционное. Допустимо `0 ≤ x ≤ width·16`, `0 ≤ y ≤ height·16`; иначе
  `Rejected { invalid }`. Ограничение размера карты: `1 ≤ width, height ≤ 65 536` логических единиц.
- **`f64` только для визуального:** `rotation`, `scale` и параметры сетки (`cell_size`, `offset_x`,
  `offset_y` в логических единицах). Они не участвуют в правилах; ядро требует от них конечности.
- **Данные листа персонажа** (`sheet_data`, сырой JSON до декларативных листов этапа 3): числа —
  только целые в пределах ±(2^53−1). Дроби храните строкой или в целых долях (например, вес в граммах).
- Протокол повышен до версии 2 (координаты стали целыми, у карты появились размеры).
- Миграция 0005: у существующих карт размер 4000×3000; координаты токенов `round(x·16)` с обрезкой
  в границы карты. Старые строки `event_log` с дробными координатами не перечитываются ядром (история).

## Последствия

- Зум/пан и рендер переводят `Units16` → логические единицы → пиксели экрана на клиенте; ядро не
  знает о пикселях.
- Сетка остаётся `f64`: шаг сетки не обязан делить размер карты, а позиции токенов к сетке не
  привязаны (привязка — функция UI).
- Хэш payload intent (ADR-0015) для координат стал проще: целые сериализуются однозначно.

## Рассмотренные альтернативы

- Координаты в пикселях изображения — ломаются при смене разрешения картинки.
- В долях клетки — ломаются при смене шага сетки, не работают на картах без сетки.
- `f64` везде с `float_roundtrip` — недетерминизм между Rust и JS в формулах.
