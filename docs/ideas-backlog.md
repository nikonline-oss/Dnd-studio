> Это **не скоуп MVP (P0)**. Документ — структурированный промпт-список идей для будущих
> срезов. Каждая идея: суть, что строить, на какие существующие механизмы ложится
> (AGENTS.md), черновой MVP самой идеи, грубый размер (S/M/L) и очередь
> (P1 / P2 / пост-MVP). Реализация любой идеи начинается с отдельной задачи и,
> если трогает архитектуру, — с ADR.

Легенда размеров: **S** — один срез на 1–2 дня, только клиент/данные; **M** — затрагивает
протокол/ядро/БД; **L** — новая подсистема.

## A. Мастеру (GM)

### GM-1. Горячие клавиши на всё частое

- **Боль:** за столом у мастера ~3 секунды на действие, пока игроки не зевнули.
- **Что строить:** бинды на бросок, скрыть/показать токен, следующий ход инициативы,
  туман, открытие/закрытие панелей. Настраиваемая схема + шпаргалка по `?`.
- **На что ложится:** существующие intents; централизованный слой shortcuts поверх
  AppShell. В скоупе P1 («полный набор горячих клавиш») уже заявлено.
- **MVP идеи:** хардкод-схема из ~10 действий, без редактора биндов.
- **Размер:** S. **Очередь:** P1.

### GM-2. Командная палитра (Ctrl+K)

- **Боль:** NPC, запись журнала, карта, правило — всё в разных панелях.
- **Что строить:** одно окно поиска по персонажам, записям журнала, картам, компендию,
  действиям («создать токен», «следующий ход»). Enter — переход/исполнение.
- **На что ложится:** существующие store'ы (characters, journal, maps, compendium);
  UI-компонент поверх, без новых intents.
- **MVP идеи:** поиск по названиям + действия-переходы, без fuzzy-ранжирования.
- **Размер:** S–M. **Очередь:** P1.

### GM-3. NPC и монстры «на лету»

- **Боль:** мастеру нужен статблок за 15 секунд прямо во время сцены.
- **Что строить:** кнопка «быстрый NPC»: имя + 2–3 числа (здоровье/атака по шаблону
  системного плагина) → готовый персонаж + токен; опционально тянуть шаблон из компендия.
- **На что ложится:** `characters` (kind: npc), шаблоны листов системного плагина,
  `create_character` + `create_token`.
- **MVP идеи:** форма из 3 полей, шаблон берётся из активного системного плагина.
- **Размер:** S. **Очередь:** P1.

### GM-4. Напоминания об окончании эффектов

- **Боль:** мастер забывает раунды боя, длительность заклинаний, горение факелов.
- **Что строить:** в начале хода токена мастеру приходит тихое напоминание
  «у токена X закончился эффект Y». Временные эффекты на токенах уже есть — нужен
  триггерный проход по ним при смене хода.
- **На что ложится:** `characters.conditions` / временные эффекты (ADR-0024), события
  инициативы (`combatants`, round/turn), системные сообщения чата.
- **MVP идеи:** проверка при `next_turn`: эффекты с истёкшей длительностью → системное
  сообщение GM.
- **Размер:** M. **Очередь:** P1.

### GM-5. Режимы бросков: скрытые, «в трубочку», запрос броска

- **Боль:** броски мастера палятся в общий чат; собрать «все киньте восприятие» —
  пять минут переписки.
- **Что строить:**
  1. скрытый бросок GM (виден только ему);
  2. бросок конкретному игроку (личный канал);
  3. кнопка «запросить бросок»: формула + список участников → у каждого пульсирует
     кнопка (см. PLR-3), результаты собираются мастеру в сводку.
- **На что ложится:** `dice_rolls`, видимость событий (Redacted-фильтрация, ADR-0022),
  новый intent запроса броска + событие-результат.
- **MVP идеи:** скрытые броски + запрос всем игрокам; сводка одним сообщением.
- **Размер:** M. **Очередь:** P1.

### GM-6. Хроника кампании

- **Боль:** «а что было в прошлый раз?» — мастер перечитывает свой журнал полчаса.
- **Что строить:** автохроника по сессиям: ключевые события (бои, смерти, находки,
  броски-нат20/нат1) собираются из `event_log` в запись журнала за сессию; мастер
  правит как обычный Markdown.
- **На что ложится:** `event_log`, `journal_entries`, сессии сервера. См. также PL-7.
- **MVP идеи:** по остановке сессии генерировать черновик хроники из журнала событий.
- **Размер:** M. **Очередь:** P2.

### GM-7. Автораскладка графа связей на доске

- **Боль:** детективные кампании живут на связях «NPC → слух → место», раскладку
  графа мастер рисует руками.
- **Что строить:** кнопка «разложить» на доске: автораскладка узлов (force-directed).
- **На что ложится:** `boards`/`board_nodes`/`board_edges`, `journal_links`. В P2 уже
  заявлено «граф миров (Cosmograph, автораскладка)» — это тот же срез, начать с досок.
- **MVP идеи:** одна кнопка, простой force-layout без библиотеки или с крошечной.
- **Размер:** M. **Очередь:** P2.

### GM-8. Таймеры мира

- **Боль:** «ритуал завершится через 3 сессии», «ярмарка на 12-й день» — мастер ведёт
  в блокноте.
- **Что строить:** трекер событий мира: название + счётчик (дни/раунды/сессии),
  напоминание при наступлении; опционально привязка к триггерам («таймер истёк →
  раскрыть запись журнала»).
- **На что ложится:** новая таблица (данные, не код) или board-узлы; события — через
  триггеры (ADR-0024).
- **MVP идеи:** список таймеров с ручным «тикнуть день» + бейдж просроченных.
- **Размер:** S–M. **Очередь:** P2.

### GM-9. Показ картинки игрокам в полный экран

- **Боль:** «смотрите, что вы видите» — показ арта сцены сейчас через заставку/чат.
- **Что строить:** кнопка на ассете/токене «показать игрокам»: у игроков картинка
  открывается поверх всего, закрывается мастером или по Esc.
- **На что ложится:** assets + новое событие показа (intent/event), видимость по ролям.
- **MVP идеи:** одна картинка, без слайдшоу и подписей.
- **Размер:** S. **Очередь:** P1.

### GM-10. Рука мастера на карте

- **Боль:** нужно тыкнуть «сюда!» всем игрокам, не двигая токены.
- **Что строить:** курсор-указка мастера, видимая всем (позиция + короткий pulse при
  клике); не сохраняется в состояние игры, чистый эфемерный оверлей.
- **На что ложится:** WS-канал, эфемерные события (как движение токенов, но без
  записи в event_log), Pixi-оверлей.
- **MVP идеи:** только позиция курсора GM, без рисования линий.
- **Размер:** S. **Очередь:** P2.

## B. Плагины (данные, без кода)

### PL-1. «Живой» компендий слухов

- **Суть:** записи-слухи с достоверностью (правда/полуправда/ложь). Мастер выдаёт слух
  игрокам → в журнале автоматически помечается, что стало известно.
- **На что ложится:** компендии + видимость журнала; поле достоверности видно только GM.
- **MVP:** тип записи компендия «слух» + кнопка «выдать игрокам».
- **Размер:** M. **Очередь:** P2. Нигде такого нет — дифференциатор.

### PL-2. Генераторы-таблицы как контент-плагин

- **Суть:** таблицы случайных encounters/погоды/имён таверн — чистые данные.
  Триггер «кнопка мастера» → бросок по таблице → запись в чат/журнал.
- **На что ложится:** триггеры-данные (ADR-0024), шаблоны триггеров в плагинах,
  движок костей. Нужен шаг триггера «бросок по таблице» (данные таблицы в плагине).
- **MVP:** таблица = список взвешенных строк; один шаблон триггера «случайный encounter».
- **Размер:** M. **Очередь:** P2. Контент-плагины люди будут писать пачками.

### PL-3. Тема-атмосфера

- **Суть:** «атмосфера одним файлом»: тема (только CSS-переменные из whitelist) +
  звуковой плейлист + триггер-шаблоны («скрип за дверью») + состояния («паника/ступор»).
- **На что ложится:** темы-плагины (P1), плейлисты, шаблоны триггеров, conditions
  системного/контентного плагина (ADR-0024).
- **MVP:** тема + плейлист + 2 триггера.
- **Размер:** S (после появления тем-плагинов). **Очередь:** P2.

### PL-4. Трекер угрозы (stealth-механика)

- **Суть:** состояния «тихо/подозрительно/тревога», триггеры «шум в зоне → +тревога»,
  шкала уровня тревоги у GM.
- **На что ложится:** состояния + триггеры (зоны, броски в зоне) ADR-0024; шкала —
  либо board-узел, либо счётчик ресурса.
- **MVP:** триггер-шаблоны + одно состояние-счётчик.
- **Размер:** M. **Очередь:** P2. В VTT такого никто не делает.

### PL-5. Триггер-шаблоны социальных механик

- **Суть:** не только урон: «персонаж получил предмет X → открыть запись Y» (уже есть),
  «бросок харизмы в зоне переговоров < 10 → NPC враждебен (состояние) + реплика в чат
  от имени NPC». Целые социальные сцены как устанавливаемые шаблоны.
- **На что ложится:** шаблоны триггеров в плагинах, give_item, зоны, состояния,
  чат от имени NPC.
- **MVP:** 2–3 готовых шаблона в системном плагине-примере.
- **Размер:** S–M (поверх существующих триггеров). **Очередь:** P2.

### PL-6. «Часы прогресса» (Blades in the Dark)

- **Суть:** сегментные часы 4/6/8 — механика, которую мастера рисуют на бумажке.
  Board + узлы + триггер «при событии → закрасить сегмент».
- **На что ложится:** доски/узлы/рёбра, триггеры. Возможно, новый тип узла «часы».
- **MVP:** тип узла «часы» с N сегментами + шаг триггера «+1 сегмент».
- **Размер:** M. **Очередь:** P2. Культовая ниша.

### PL-7. Сводка сессии

- **Суть:** события уже логируются — плагин/фича-сводка: «за сессию партия убила
  4 врагов, нашла 2 предмета, потратила 3 зелья». Конец «так, а что было в прошлый раз?».
- **На что ложится:** `event_log`, `dice_rolls`, сессии. Пересекается с GM-6
  (хроника): GM-6 — повествование, PL-7 — статистика.
- **MVP:** одна сводка по остановке сессии, формируется запросами к event_log.
- **Размер:** S–M. **Очередь:** P1–P2.

### PL-8. «Наследие» между кампаниями

- **Суть:** экспорт «летописи мира» из кампании в плагин: следующая кампания в том же
  мире импортирует последствия (NPC мёртв, город разрушен).
- **На что ложится:** формат плагина (компендии/шаблоны), экспорт кампании.
- **MVP:** экспорт выбранных записей журнала/персонажей как контент-плагин.
- **Размер:** M. **Очередь:** пост-MVP. Опенсорс-комьюнити расхватает.

## C. Игрокам (PLR)

### PLR-1. «Что я могу сделать?» — кнопки вместо знания правил

- **Боль:** новичок забывает про действие/бонусное/реакцию.
- **Что строить:** лист персонажа в свой ход подсвечивает доступные действия
  («Атаковать», «Отойти»), кнопки сереют после использования. Экономика действий
  задаётся системным плагином.
- **На что ложится:** инициатива (round/turn) + вычисляемые поля листа + декларативный
  layout листа. Зависит от ресурсов/действий в системном плагине.
- **MVP:** подсветка «твой ход» + кнопки действий без жёсткого трекинга экономики.
- **Размер:** M–L. **Очередь:** P2. Киллер-фича для новичков, у конкурентов нет.

### PLR-2. Бросок из листа в одно касание с контекстом

- **Боль:** игрок не должен помнить «1d20+7».
- **Что строить:** кнопка «Атака мечом» кидает попадание и урон одним действием,
  спрашивает «с преимуществом?»; статус «вдохновение» — галочка, которая сама
  предлагает преимущество и сама снимается.
- **На что ложится:** кнопки бросков листа (dnd-dice/dnd-expr), состояния персонажа.
- **MVP:** связанные броски (попадание+урон) + модификатор adv/dis в диалоге броска.
- **Размер:** M. **Очередь:** P1–P2.

### PLR-3. Подсветка «тебя спрашивают»

- **Боль:** игрок прослушал свою очередь, отвлёкшись на чай.
- **Что строить:** запрос броска/ход/личка → пульсирующая кнопка поверх карты +
  звук + бейдж; один клик — результат ушёл. Невозможно пропустить.
- **На что ложится:** запрос бросков GM (GM-5), события инициативы, уведомления.
- **MVP:** пульс + звук на «твой ход» и на запрос броска.
- **Размер:** S–M. **Очередь:** P1. Лучшее соотношение «ощущение/цена».

### PLR-4. Личная лента «моё»

- **Боль:** «тебе шепнул мастер», «по тебе попали на 8» тонет в общем чате.
- **Что строить:** лента событий, отфильтрованная под конкретного игрока.
- **На что ложится:** Redacted-фильтрация видимости (ADR-0022), чат/системные
  сообщения — лента поверх них почти бесплатна.
- **MVP:** вкладка «моё» в чате с фильтром по персонажу/упоминаниям.
- **Размер:** S. **Очередь:** P1.

### PLR-5. Карта глазами персонажа

- **Боль:** игрок принимает решения по картинке, не по таблицам.
- **Что строить:** мой токен с кольцом состояния прямо на карте; враги с метками
  качественного здоровья (ранен/тяжело ранен по порогам системного плагина).
- **На что ложится:** качественное здоровье (пороги 75/25/0% из системного плагина),
  Pixi-рендер токенов, состояния токенов (ally/neutral/enemy — в работе).
- **MVP:** цветное кольцо/бейдж состояния на токене.
- **Размер:** S–M. **Очередь:** P1 (частично пересекается с P1 «HP/ресурсы на токенах»).

### PLR-6. «Мои заметки» — личный блокнот игрока

- **Боль:** игрок ведёт заметки на бумажке рядом с клавиатурой.
- **Что строить:** личные записи игрока (не общий журнал), кнопка «в мои заметки»
  из чата/записи мастера.
- **На что ложится:** journal_entries с видимостью «только я» (расширение visibility).
- **MVP:** личная папка журнала на участника.
- **Размер:** S. **Очередь:** P2.

### PLR-7. Шёпот без страха ошибиться

- **Боль:** классика — прислал секретное всем.
- **Что строить:** личка выбором из списка участников (не командой), визуально другой
  цвет пузыря, явный индикатор «только для X» перед отправкой.
- **На что ложится:** chat_messages (видимость/адресат), participants.
- **MVP:** выбор адресата + отдельный стиль сообщений.
- **Размер:** S. **Очередь:** P1.

### PLR-8. Реакции и «поднятая рука»

- **Боль:** в онлайне игроку некуда вставить слово, пока мастер описывает сцену.
- **Что строить:** кнопка «рука» → тихий бейдж у мастера; быстрые реакции на сообщения
  (🔥 на крутой бросок).
- **На что ложится:** chat_messages (реакции как отдельные события), бейджи у GM.
- **MVP:** «рука» + 3–4 фиксированные реакции.
- **Размер:** S. **Очередь:** P2.

### PLR-9. Отыгрыш персонажа в чате

- **Боль:** игроки любят, когда реплики выглядят как диалог из игры.
- **Что строить:** аватар + имя персонажа на сообщениях, быстрый переключатель
  «говорить от персонажа / от себя» (уже частично: sender_name на момент записи есть).
- **На что ложится:** chat_messages.sender_name, assets (аватары), выбор активного
  персонажа.
- **MVP:** переключатель «я/персонаж» + аватар в сообщении.
- **Размер:** S. **Очередь:** P1–P2.

### PLR-10. «Мой бросок дня» — личная статистика кубов

- **Боль:** игроки обожают спорить «у кого кубы заряжены».
- **Что строить:** статистика за сессию: среднее, криты, единицы — по игроку.
- **На что ложится:** `dice_rolls` (user_name на момент записи) — чистый запрос к БД.
- **MVP:** панель статистики текущей сессии.
- **Размер:** S. **Очередь:** P1. Лучшее соотношение «ощущение/цена».

### PLR-11. Инвентарь, которым пользуются

- **Боль:** передача/использование предметов — переписка с мастером.
- **Что строить:** перетащил зелье на портрет союзника → «передать»; кнопка «выпить
  зелье» на предмете → сразу бросок лечения.
- **На что ложится:** инвентарь системного плагина (ADR-0024), give_item, триггеры,
  кнопки бросков.
- **MVP:** drag&drop передача + кнопка использования с броском.
- **Размер:** M. **Очередь:** P2.

### PLR-12. Ничего не потерять (восстановление UI-состояния)

- **Боль:** свернул приложение/пропал интернет → вернулся не туда.
- **Что строить:** восстановление открытой вкладки, прочитанного журнала, черновика
  сообщения после реконнекта.
- **На что ложится:** реконнект/ресинк (есть) + персистентный UI-state (Zustand persist
  или поля в campaign_meta).
- **MVP:** восстановление активной вкладки и черновика чата.
- **Размер:** S. **Очередь:** P1.

## Приоритеты (сводно)

Лучшее соотношение «ощущение / цена разработки» — всё строится на уже существующих
событиях и логах, без новой архитектуры:

1. **PLR-3** — непропускаемый запрос броска / «твой ход» (звук + бейдж).
2. **PLR-4** — личная лента «моё» поверх Redacted-фильтрации.
3. **PLR-10** — статистика кубов (один запрос к `dice_rolls`).
4. **GM-5** — скрытые/личные броски и запрос броска кнопкой.
5. **GM-9** — показ картинки игрокам в полный экран.

Дальше по очереди P1: GM-1 (хоткеи), GM-2 (Ctrl+K), GM-3 (NPC на лету), GM-4
(напоминания эффектов), PLR-5 (кольца состояний), PLR-7 (шёпот), PLR-12 (восстановление UI).
