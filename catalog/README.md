# Каталог плагинов DndStudio

Это шаблон отдельного репозитория каталога (ADR-0006, ADR-0060). Приложение читает отсюда
подписанный `index.json`, скачивает пакеты по указанным в нём ссылкам и проверяет подписи.

## Как устроена публикация

1. Автор присылает PR: каталог `plugins/<id>/<version>/` с исходниками пакета либо готовый
   `.dndplugin` и строку в `submissions.json`.
2. Workflow `publish.yml` собирает пакеты `plugin-tool pack`, проверяет их
   `plugin-tool validate`, собирает и подписывает индекс `plugin-tool index`.
3. Архивы прикрепляются к GitHub Release тега `plugins-<дата>`, индекс публикуется в `gh-pages`
   (или в сам релиз — см. `CATALOG_BASE_URL`).
4. Опубликованная версия неизменяема: тот же `id`/`version` с другим хэшем — ошибка сборки.

## Секреты

| Секрет                | Назначение                                                    |
| --------------------- | ------------------------------------------------------------- |
| `CATALOG_SIGNING_KEY` | приватный ключ Ed25519 в PKCS#8 (base64 от файла `keygen -o`) |

Открытый ключ из `plugin-tool keygen` попадает в приложение (поле «Открытый ключ» в каталоге или
сборка). Потеря приватного ключа означает выпуск нового `key_id`; старые индексы продолжат
проверяться, пока приложение знает прежний ключ.

## Проверка перед PR

```bash
plugin-tool validate plugins/<id>/<version>
plugin-tool pack plugins/<id>/<version>
```

## Отзыв версии

Правка `revoked` в `submissions.json` (или в индексе) и повторная публикация. Установленная копия
продолжает работать; новые установки и обновления этой версии запрещены.

## Чего здесь нет

- аккаунтов, рейтингов и отзывов (пост-MVP);
- ручной модерации сверх проверки CI;
- хранения приватного ключа в репозитории — только секрет CI.
