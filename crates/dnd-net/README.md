# dnd-net

Клиент сервера сессий (ADR-0022), позже — и индекса плагинов.

**Разрешённые зависимости (внутренние):** `dnd-protocol`. В тестах также `dnd-session-server`,
`dnd-db`, `dnd-game-core` — тесты идут против настоящего сервера в том же процессе.

- `HttpClient` — создание сессии (host token + архив кампании), вход по `gm_key` или коду доступа,
  остановка, экспорт, ассеты (хэш содержимого проверяется).
- `Connection` — WS с реконнектом (backoff 1→30 с) и ping каждые 15 с; соединение мертво после 45 с
  тишины. Ответы сопоставляются с intents (`accepted` / `rejected`).
  - Офлайн ждут только чат (младше 5 мин) и движения токенов, не больше 100 штук. Остальное сразу
    получает `Offline`.
  - После реконнекта приходит снапшот, затем уходит очередь.
  - Неподтверждённые intents повторяются с тем же `intent_id`, если им можно ждать, иначе — ошибка
    `ConnectionLost`; вслепую они не переигрываются (CLAUDE.md §7).
- TLS — rustls с провайдером ring и системными сертификатами, как у Tauri.
