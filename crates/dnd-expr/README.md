# dnd-expr

Безопасный минимальный язык выражений для плагинов систем правил (ADR-0005): вычисляемые поля листов,
формулы инициативы, пороги, условия.

**Разрешённые зависимости (внутренние):** нет. Без I/O, без циклов и пользовательских функций, лимиты
глубины/длины. Поля передаёт вызывающий через трейт `Context`.

**Этап реализации:** 3 — Плагины

## Значения

- **Число** — точная дробь `i64 / i64` (всегда нормализована, знаменатель > 0). Переполнение `i64` в
  числителе или знаменателе — ошибка `overflow`, никакого округления и плавающей точки.
- **Логическое** — `true` / `false`.

Литералы — только неотрицательные целые (`0`, `42`; минус — унарный оператор), `true`, `false`.
`7 / 2` даёт `7/2`, а не `3`: для целого используйте `floor`, `ceil` или `round`.

## Грамматика

```text
expr    = or
or      = and { "||" and }
and     = cmp { "&&" cmp }
cmp     = add [ ("==" | "!=" | "<=" | "<" | ">=" | ">") add ]      (не цепочится)
add     = mul { ("+" | "-") mul }
mul     = unary { ("*" | "/" | "%") unary }
unary   = ("-" | "!") unary | primary
primary = integer | "true" | "false" | "@" path | "(" expr ")"
        | "if" expr "then" expr "else" expr
        | name "(" [ expr { "," expr } ] ")"
path    = ident { "." ident },   ident = [A-Za-z_][A-Za-z0-9_]*
```

Пробелы (` `, `\t`, `\r`, `\n`) допустимы между любыми токенами. Приоритет — от слабого к сильному:
`if` → `||` → `&&` → сравнения → `+ -` → `* / %` → унарные `- !`. Бинарные операторы
левоассоциативны; сравнения не цепочатся (`1 < x < 3` — ошибка, пишите `1 < x && x < 3`).
Ветка `else` жадная: `1 + if c then 2 else 3 + 4` = `1 + (if c then 2 else (3 + 4))`.

| Конструкция                     | Типы                     | Смысл                                                    |
| ------------------------------- | ------------------------ | -------------------------------------------------------- |
| `+ - * /`                       | числа                    | точная арифметика; деление на 0 — `division_by_zero`     |
| `%`                             | целые                    | остаток с округлением вниз (знак делителя): `-7 % 3 = 2` |
| `< <= > >=`                     | числа                    | → логическое                                             |
| `== !=`                         | оба операнда одного типа | → логическое; число с логическим — `type_mismatch`       |
| `&& \|\| !`                     | логические               | `&&`/`\|\|` вычисляются лениво (короткое замыкание)      |
| `if c then a else b`            | `c` — логическое         | вычисляется только выбранная ветка                       |
| `min(a, …)`, `max(a, …)`        | числа, 1+ аргументов     |                                                          |
| `floor(x)`, `ceil(x)`, `abs(x)` | число                    |                                                          |
| `round(x)`                      | число                    | половины — от нуля: `round(5/2) = 3`, `round(-5/2) = -3` |
| `@name`, `@a.b`                 | что вернёт `Context`     | ссылка на поле; имена регистрозависимы                   |

Других функций, переменных, циклов, строк и доступа к чему-либо, кроме переданного `Context`, нет.

### Примеры

```text
floor((@str - 10) / 2)                         модификатор характеристики D&D (1 → -5, 30 → 10)
2 + floor((@level - 1) / 4)                    бонус мастерства
@str_mod + @proficiency                        бонус атаки (ссылки на другие вычисляемые поля)
max(1, @hit_die / 2 + 1 + @con_mod)            среднее HP за уровень, не меньше 1
if @hp.current <= 0 then 0 else if @hp.current * 4 < @hp.max then 1 else 2
@dex >= 13 && !@armor.heavy
```

## Лимиты (`dnd_expr::limits`)

- длина выражения ≤ 1024 символов (`too_long`);
- вложенность ≤ 32 уровней: каждая скобка, вызов функции, `if` и унарный оператор — уровень
  (`too_deep`). Длинные цепочки одного уровня (`1 + 1 + … + 1`) вложенностью не считаются и хранятся
  плоско, так что глубина рекурсии ограничена вложенностью. На предельной вложенности разбору нужно
  ≈ 256 КБ стека в release и ≈ 1 МБ в debug — меньше стандартных 2 МБ потоков tokio и тестов.

## API

```rust
let expr = dnd_expr::Expr::parse("floor((@str - 10) / 2)")?;  // синтаксис, арность, лимиты
expr.references();                     // BTreeSet<&str>: {"str"} — пути без `@`
let v: Value = expr.eval(&sheet)?;     // sheet: impl Context
let n: i64 = expr.eval_integer(&sheet)?; // = eval + Value::as_integer (иначе `not_an_integer`)

// Вычисляемые поля листа: имя → формула; порядок по зависимостям, все результаты — целые.
let computed = dnd_expr::Computed::resolve(&definitions, &sheet)?; // BTreeMap<String, String>
computed.get("str_mod");               // Option<i64>; values() / into_values(): BTreeMap<String, i64>
let scope = computed.with_sheet(&sheet); // Context: сначала вычисляемые, потом лист
// для бросков: dnd_dice::ExprFields(scope) реализует dnd_dice::FieldLookup
```

- `Context { fn lookup(&self, path) -> Result<Value, LookupError> }`; готовые реализации —
  `BTreeMap`/`HashMap<String, Value | i64>`, `&C`, `NoContext`. `LookupError::Unknown` превращается в
  `unknown_reference`, `Other(msg)` — в `reference`.
- `Value::{Number(Rational), Bool(bool)}`; `Rational::new(num, den)`, `numer()`, `denom()`,
  `to_integer()`. `Value` реализует `From<i64 | bool | Rational>` и `Display` (`7/2`, `true`).
- `Computed::resolve`: имена определений — валидные пути (`invalid_field_name`); ссылка должна быть
  вычисляемым полем или существовать в листе — проверяется заранее, даже в невыбранной ветке `if`
  (`unknown_reference`); цикл (в т. ч. ссылка поля на само себя) — `cycle` со списком полей
  `a -> b -> a`; дробь или логическое в результате — `not_an_integer`. Вычисляемое поле затеняет
  одноимённое поле листа. Ошибки внутри формулы оборачиваются в `ExprError::Computed { field, source }`.
- `ExprError`: `code()` — стабильный snake_case-код (`syntax`, `too_long`, `too_deep`,
  `type_mismatch`, `division_by_zero`, `overflow`, `not_an_integer`, `cycle`, …; у `Computed` — код
  источника), `offset()` — байтовое смещение в исходном тексте, если есть, `Display` — сообщение на
  английском (локализация — по `code()` в UI).
- `Display` у `Expr` — каноничная форма: одиночные пробелы вокруг бинарных операторов и ключевых слов,
  `f(a, b)`, только необходимые скобки (`if` внутри оператора всегда в скобках);
  `parse(display(e)) == e`. Равенство `Expr` структурное: `1+2` и `(1) + 2` равны.
- serde: `Expr` сериализуется **исходной строкой** (как написал автор плагина), десериализация парсит
  заново — лимиты не обойти, а смещения ошибок вычисления указывают в тот же текст. Каноничная форма
  может быть длиннее исходной (пробелы) и потому не используется для хранения.
