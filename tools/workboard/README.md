# Workboard — доска работ и просмотр репозитория

Инструмент разработки: канбан по задачам, чтение `docs/` и рабочего дерева. Не часть продукта
DndStudio (CLAUDE.md §12), зависимостей нет — только Node и `git` в `PATH`.

## Быстрый старт

```bash
pnpm workboard                  # http://127.0.0.1:8090
node tools/workboard/server.mjs # то же самое без pnpm
```

| Переменная        | По умолчанию | Смысл                                                          |
| ----------------- | ------------ | -------------------------------------------------------------- |
| `WORKBOARD_PORT`  | `8090`       | порт                                                           |
| `WORKBOARD_HOST`  | `127.0.0.1`  | интерфейс; `0.0.0.0` — доступ извне                            |
| `WORKBOARD_TOKEN` | —            | если задан, API требует `?token=…` или `Authorization: Bearer` |
| `WORKBOARD_URL`   | этот сервер  | адрес, к которому обращается CLI (см. ниже)                    |

Если задан токен, откройте страницу как `http://host:8090/?token=…` — страница его запомнит.
Интерфейс (HTML/CSS/JS) отдаётся без пароля, в нём нет данных; закрыт только API.

## Как ведётся работа

Четыре колонки — это состояния задачи, а не украшение:

1. **Бэклог (`backlog`)** — сюда владелец пишет замечания и пожелания: по одной карточке на
   мысль, своими словами. Приоритет задаётся у карточки.
2. **В работе (`doing`)** — исполнитель взял карточку: разбирает, правит код, запускает проверки.
3. **Нужно проверить (`verify`)** — сделано и проверено исполнителем; у каждой проверки в
   карточке стоит результат и короткая заметка, что именно смотрели. Сюда же попадает то, что
   нельзя проверить здесь (например, запуск на Windows).
4. **Готово (`done`)** — карточку закрыл человек: он сам посмотрел результат и перенёс её.

Правило: **в `done` карточку переносит тот, кто проверял результат глазами**, а не тот, кто
писал код. Исполнитель останавливается на `verify`.

У карточки: заголовок, описание, тип (`task` / `bug` / `question`), приоритет
(`low` / `normal` / `high`), список файлов и список проверок. Проверка — это пара
«что проверяли» + состояние `pass` / `fail` / `pending` + заметка с результатом.

## Интерфейс

- **Доска** — четыре колонки; карточку можно перетащить, клик открывает её в панели справа:
  описание, файлы, проверки (по клику меняется состояние), кнопки перемещения.
- **Файлы** — дерево `docs/`: клик по файлу открывает его справа, Markdown рендерится.
  `GET /api/file?path=…` отдаёт любой файл репозитория, кроме закрытых путей, так что
  корневой `README.md` тоже доступен — запросом, без отдельной кнопки в интерфейсе.
- **Изменения** — `git status` рабочего дерева; по клику показывается diff файла.

Данные лежат в `docs/workboard/tasks.json` — рядом с документацией, чтобы попадать в коммиты.
Запись атомарная: временный файл и `rename`.

## CLI

Всё то же можно делать из терминала — этим пользуется и агент, и человек:

```bash
node tools/workboard/cli.mjs list [колонка]           # что где лежит, с прогрессом проверок
node tools/workboard/cli.mjs add <колонка> "<заголовок>" ["<описание>"]
node tools/workboard/cli.mjs move <id> <колонка>       # backlog|doing|verify|done
node tools/workboard/cli.mjs check <id> pass|fail|pending "<что проверяли>" ["<заметка>"]
node tools/workboard/cli.mjs append <id> "<текст>"     # дописать в описание
```

`<id>` — полный идентификатор (`t-a873d105`) или уникальное начало: `t-a873` подойдёт, если он
один. `check` с уже существующей формулировкой **обновляет** её, а не добавляет вторую.

Пример полного прохода:

```bash
WORKBOARD_TOKEN=… node tools/workboard/cli.mjs add backlog "предметы: модалки" "Поля ввода не должны быть в карточке"
WORKBOARD_TOKEN=… node tools/workboard/cli.mjs move t-1a2b doing
WORKBOARD_TOKEN=… node tools/workboard/cli.mjs check t-1a2b pass "cargo test -p dnd-game-core" "29 наборов, 0 падений"
WORKBOARD_TOKEN=… node tools/workboard/cli.mjs move t-1a2b verify
```

Если сервер запущен и задан `WORKBOARD_TOKEN` с тем же значением, CLI пишет через API — открытая
в браузере доска подхватит изменение на следующем запросе. Если сервер недоступен, CLI правит
`docs/workboard/tasks.json` напрямую; файл один и тот же, поэтому результат одинаков.

## Запуск на сервере (пример)

Доска умеет жить отдельной службой, если нужно смотреть её не со своей машины:

```ini
# /etc/systemd/system/dnd-workboard.service
[Unit]
Description=DndStudio workboard
After=network.target

[Service]
WorkingDirectory=/path/to/Dnd-studio
Environment=WORKBOARD_HOST=0.0.0.0
Environment=WORKBOARD_PORT=8090
EnvironmentFile=/path/to/workboard.env   # WORKBOARD_TOKEN=…
ExecStart=/usr/bin/node tools/workboard/server.mjs
Restart=always
```

```bash
systemctl enable --now dnd-workboard
journalctl -u dnd-workboard -f
```

Токен задавайте всегда, если порт открыт наружу: API пишет в файл задач. Без TLS это инструмент
для доверенной сети; для публичного доступа ставьте перед ним обратный прокси.

## Границы

- Читает файлы репозитория, пишет только `docs/workboard/tasks.json`; ничего не исполняет и не
  собирает. Проверки кода запускаются отдельно (`tools/ci/local-ci.sh`), а в карточку попадает
  только их результат.
- Отдаётся весь репозиторий, кроме `.git/`, `node_modules/`, `target/`, `.env` и ключей
  (`.pem`, `.key`, `.pkcs8`, `id_rsa`, `id_ed25519`); выход за корень отклоняется.
- Это инструмент для одного человека, а не многопользовательский сервис: нет учётных записей,
  истории и прав. Общий доступ — через токен и сеть, без разграничения ролей.
