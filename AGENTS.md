# Работа над DndStudio

Продуктовые границы и архитектура: [CLAUDE.md](CLAUDE.md).
Актуальная очередь и зависимости: [docs/roadmap.md](docs/roadmap.md).

## Проверки по запросу владельца

- После каждой мелкой правки запускать только связанные проверки: выбранные Rust-тесты,
  соответствующие Vitest-файлы, форматирование изменённых файлов; типы и bindings,
  если затронуты контракты. Выбирать по последствиям изменения, а не по числу строк.
- После серии связанных изменений запускать один полный CI. Серия заканчивается,
  когда завершён вертикальный срез с проверяемым пользовательским сценарием.
  Мелкий коммит внутри серии не требует отдельного полного прогона.
- Полный набор: `bash tools/ci/local-ci.sh` и
  `pnpm --filter @dndstudio/desktop build` для production build и проверки типов.
- После сбоя сначала исправить причину и точечно повторить упавшие проверки,
  затем завершить полный набор. После успешного полного CI повторять его при
  новых изменениях или нерешённой проблеме, а не после каждого промежуточного шага.
- Кандидат релиза проверять целиком. В результате указывать выполненные целевые
  проверки, полный прогон и недоступные проверки; не называть неполный прогон зелёным CI.
- Для документации точечные проверки — форматирование, локальные ссылки,
  согласованность ID/зависимостей и `git diff --check`; не добавлять тесты,
  повторяющие текст документа. Правило полного CI после серии сохраняется.

Это правило заменяет старые требования полного CI перед каждой мелкой правкой
или каждым коммитом, включая исторические планы в `docs/`.

## Доска работ

Задачи и их проверки ведутся на доске: [tools/workboard/README.md](tools/workboard/README.md)
(`pnpm workboard` → http://127.0.0.1:8090). Замечания владельца приходят карточками в
`backlog`; исполнитель ведёт карточку в `doing` → `verify` и записывает результат каждой
проверки командой `check`. В `done` карточку переносит тот, кто проверил результат глазами.
